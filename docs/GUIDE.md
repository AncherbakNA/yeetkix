# Руководство по YEETKIX 1.0

## Установка и файлы проекта

Нужны macOS 14+, Apple Silicon, Command Line Tools со Swift 5.9+ и интернет для первой загрузки зависимости. Для установки инструментов Apple выполните `xcode-select --install` и завершите системную установку.

```sh
git clone https://github.com/AncherbakNA/yeetkix.git
cd yeetkix
bash scripts/build-app.sh
open build/Yeetkix.app
```

Приложение лежит в `build/Yeetkix.app` внутри клонированной папки. Его можно скопировать в «Программы». Настраивая доступ macOS, используйте выбранную установленную копию. Сборка для Intel не поддерживается.

`bash scripts/package-release.sh` создаёт приложение, ZIP, DMG и SHA-256 в `build/`. Предыдущая сборка приложения сохраняется в `build/Previous/`. `build/` и `.build/` исключены из Git и создаются при сборке. Подпись ad hoc локальная; Developer ID и нотариализация пока не настроены. Подробности — в [RELEASE.md](RELEASE.md).

## Основной порядок работы

1. Выберите раздел и запустите сканирование.
2. Проверьте состав, пути и даты файлов. Кнопка поиска у строки открывает её в Finder.
3. Нужные файлы добавьте в исключения через контекстное меню или настройки.
4. Отметьте ненужное, откройте подтверждение и проверьте выбранные пути.
5. После переноса результат появится в «История очистки». Кнопка «Восстановить» возвращает объект в исходное место.

Сканирование ничего не удаляет. Минимальный возраст кэшей и журналов выбирается в настройках: 7, 14 или 30 дней. Возраст не означает, что файл больше не нужен.

## UTM и данные в другом месте

Выберите UTM в разделе «Приложения» и дождитесь проверки мест хранения. Проверяются обычные каталоги Library, sandbox, поддерживаемые Registry/VMList/bookmarks и Spotlight. `.utm` показывается целым пакетом, содержащим конфигурацию и виртуальный диск; VM по умолчанию не выбраны.

Для нестандартного расположения или неиндексируемого диска используйте «Проверить папку с .utm…». Внешние ISO, подключённые диски и общие папки Mac не объявляются собственностью UTM только по ссылке в реестре. Недоступный пакет нельзя выбрать для переноса, пока не проверено его содержимое.

«Добавить файл или папку…» явно связывает конкретные данные с выбранным приложением. Выбор сохраняется локально с bookmark и идентичностью объекта. Он не отмечается автоматически. В подтверждении требуется отдельная отметка о личных данных. Пункт контекстного меню «Убрать связь с приложением» удаляет только привязку.

Общие корни, каталоги ключей и учётных данных, содержимое `.app` добавить нельзя. Общие группы защищены, пока их использует установленный владелец. Наличие запущенного приложения или инструмента повторно проверяется перед переносом.

## Отчёт, остановка и права доступа

«Отчёт…» открывает прокручиваемый список всех запланированных мест, включая непроверенные после остановки или лимита. Есть поиск по пути/статусу, фильтр ограничений и сохранение JSON. Экспорт содержит метаданные и локальные пути; содержимое файлов и bookmarks доступа не включаются. Перед отправкой отчёта другим людям проверьте личные сведения.

| Статус | Значение |
| --- | --- |
| Проверена | Место проверено по правилам выбранного раздела |
| Папки нет | Ожидаемый каталог не найден, например DerivedData до первой сборки Xcode |
| Не удалось проверить | Ошибка чтения или ограничения доступа; смотрите подробности |
| Защищена | Работающее приложение/инструмент или исключение |
| Превышено время ожидания | Нет ответа файловой системы; это не означает пустую папку |
| Пропущена | Место пропущено или не проверено после остановки |
| Достигнут лимит | Полный обход не выполнен |

Обычные места проверяются отдельными процессами с тайм-аутом 20 секунд без прогресса. Для Caches/Logs sandbox-контейнеров действует 5 секунд, для места поиска связанных данных приложения — 10 секунд. Сообщения прогресса продолжающегося обхода продлевают ожидание. Лимит обычного прохода — 250 000 объектов. Уже найденные данные сохраняются при остановке и ошибке следующего места.

Подключите точную папку в «Настройки» → «Доступ к папкам», если это нужно. Отдельными разрешениями управляет macOS: «Системные настройки» → «Конфиденциальность и безопасность» → «Полный доступ к диску». Предоставлять доступ решает пользователь. После изменения системных разрешений перезапустите приложение и повторите проверку.

## Восстановление и освобождение места

«Восстановить» не перезаписывает существующие файлы. Проверяются исходный путь, идентичность объекта в Корзине и манифест целой папки. Конфликт или изменение блокирует операцию. Если исходной папки больше нет, объект остаётся в Корзине для ручного восстановления через Finder.

Перенос в Корзину сам по себе не освобождает место. Окончательную очистку выполняет пользователь в Finder; после неё приложение не может вернуть данные. Размеры логические: APFS-сжатие, клоны, жёсткие ссылки и разреженные VM могут менять физический объём.

Docker и simctl используют отдельный журнал и необратимые штатные команды с отдельным подтверждением. Тома Docker не очищаются. Полный Xcode нужен для функций симуляторов, запущенный локальный Docker — для его ресурсов.

## Где лежат данные приложения

```text
~/Library/Application Support/local.luma.cleaner/history.json
~/Library/Application Support/local.luma.cleaner/history.json.journal
~/Library/Application Support/local.luma.cleaner/managed-history.jsonl
~/Library/Preferences/local.luma.cleaner.plist
```

История находится в первых файлах. Исключения, возраст, bookmarks и ручные привязки сохраняются через UserDefaults; записью plist управляет macOS. Bundle ID оставлен от ранней версии для совместимости. История содержит локальные пути и не входит в исходники репозитория.

Повреждённый журнал не перезаписывается автоматически: перенос отключается, сканирование остаётся доступным. В текущей локальной сборке канал сетевых обновлений не настроен.

## Код и проверка изменений

`Sources/Luma/` — SwiftUI-экраны и состояние. `Sources/LumaCore/` — сканеры, правила SafetyPolicy, манифесты, дочерние процессы и CleanupService. `Tests/LumaCoreTests/` — исполняемые проверки без XCTest. `scripts/` — сборка, упаковка и будущая подпись. Встроенное руководство открывается через меню «Справка».

Поток обычной операции: сканирование → кандидаты и статусы → выбор → подтверждение → повторная проверка → запись намерения → системная Корзина → запись результата. Восстановление использует точный путь, который система вернула после переноса.

```sh
swift run -c release -debug-info-format none LumaChecks
```

Тесты используют только собственные временные файлы, искусственные приложения и VM, подставные команды Docker/simctl. Для ручного теста создайте отдельный файл, выберите только его, перенесите в Корзину, восстановите и сравните содержимое. Настоящие пользовательские файлы ради проверки удаления не используйте.
